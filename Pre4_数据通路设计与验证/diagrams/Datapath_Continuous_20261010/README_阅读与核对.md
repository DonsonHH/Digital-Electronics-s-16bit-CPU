# 16 位 CPU 连续连线图

本版按 Vivado/rtl 中的真实信号来源重建，采用回折布局。图中每个输入端都有连续线路连接到实际来源；同名信号不再通过两块独立标签代替线路。反向摆放的 EX/MEM、MEM/WB 等寄存器从右侧 D 输入，向左侧 Q 输出。

## 文件

- `Datapath_Trace_Viewer.html`：推荐用 Chrome 或 Edge 打开。图像、连线数据和交互均内嵌，可离线使用。
- `Datapath_Continuous.svg`：同一张图的矢量原稿，可无限放大。
- `Datapath_Continuous.png`：同一张图的高清静态图，宽 12000 像素。

## 怎么顺着一条线路看

1. 滚轮缩放、拖动平移；单击线路，高亮同一驱动信号的全部分支。
2. 右侧 Source 定位源端；Sinks 列出并定位每个接收端。
3. 输入进入流水寄存器后，先阅读黄色框里的实际 RTL 赋值式和捕获条件，再点击 `Next Q (rising edge)`，继续到对应输出字段。
4. 对 MUX、ALU、存储器等功能块，按图内选择条件和功能说明，从右侧选择要继续查看的输出。
5. `All wires` 恢复全部连线；`Overview` 回到整图。
6. `Back` 返回上一个信号及其视口；`Fit signal` 将所选信号的完整线路放入视野。Recently viewed 是浏览历史，不表示各项之间都有电路连接。
7. 可直接搜索 `im_addr`、`dm_addr`、`x_store_data` 等别名，也可输入 `wb_data[15:0]`。

例如追踪 STR 写入值：搜索 `rd_fwd`，查看 EX/MEM 的 `x_store_data` 输入，选择 `Next Q: m_store_data`，再定位 DM 的 `dm_din`。这条支路绕开 ALU 与 WB。搜索 `m_exec_value` 可以看到地址、MEM 前递与普通结果继续向 WB 传递的所有实际分支。

实心点表示真正相连；跨线桥表示仅交叉。寄存器内部虚线及小寄存符号表示下一上升沿的字段传递，不表示直接组合短接。高亮的是实际连接，可能包括当前指令未选用的分支；MUX 选择、valid/fault 和写使能决定它是否生效。

寄存器内部的 `G` 标记表示该字段赋值含门控表达式；`E` 表示捕获使能，例如 d_pc 只有 fetch_accept 时才更新。悬停字段可见具体赋值，查看器右侧也会显示。复位具有优先级。

## 核对结果

- 37 个功能块或寄存器组，134 个有唯一来源的信号网络，227 条明确的接收端连接。
- 对照实际 RTL 实例核对 10 个模块、93 个端口及位宽；54 组寄存器字段输入/输出对应赋值已核对。
- 12 条典型路径的连线检查通过，包括 LDR、STR、普通写回、前递、CMP/JZ、标志提交、load-use 和故障停止。
- 线路端点、箭头进入/离开方向、穿越无关模块、不同信号共用同一直线段、模块文字越界检查均无发现。
- 实际浏览器测试通过：信号检索、鼠标点击整条信号高亮、接收端定位、跨寄存器继续追踪。
