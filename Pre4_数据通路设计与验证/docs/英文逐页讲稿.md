# 1. Pre4: Pipelined Datapath

Presenter A; 20 seconds.

Today we present the datapath for ISA version 1.4. We connect the instruction semantics to the five-stage hardware, trace arithmetic, memory and branch instructions, and show actual Vivado validation. The source, testbench and diagrams use the same design version.

Sources: 16位流水线CPU核心设计文档 v1.4 (2026-10-08), §§1–4

# 2. Version 1.4 changes the implementation

Presenter A; 45 seconds.

The latest specification changes more than the presentation wording. It rearranges the opcode table, adds SUB immediate and defines separate Z, C and V updates. We therefore migrated the decoder and the ALU. MOV uses opcodes zero and one, load/store use two and three, and jump, conditional jump and HALT use C, D and E. The arithmetic core is a two-level CLA. Subtraction saves carry as no borrow. Only CMP updates Z, while ADD and SUB update C and V. These changes make the older Pre3 binary programs and decoder incompatible with this build.

Sources: 16位流水线CPU核心设计文档 v1.4 (2026-10-08), §§1–4; rtl/isa_decode.v; rtl/addsub16_cla.v

# 3. Instruction set and encoding

Presenter A; 50 seconds.

The fixed instruction has four opcode bits, two Rd bits, two Rs bits and eight immediate bits. The table shows all fourteen legal codes. R0 is writable. MOV, ADD and SUB immediate use an unsigned constant. Load/store offsets and JZ use a signed eight-bit displacement. CMP has no register write. A successful store completes in MEM. Reserved B and F produce fault tokens with no data writes. The unused fields are zero in the assembler image and ignored by the decoder. This avoids accidentally mixing the old opcode table with the new datapath.

Sources: 16位流水线CPU核心设计文档 v1.4 (2026-10-08), §§1–4 §§1.2–1.5

# 4. Core input and output contracts

Presenter A; 40 seconds.

The core uses one clock and synchronous reset. It exports sixteen-bit word addresses and fixed-latency enables to separate instruction and data memories. The total is eighty-seven logical interface bits, not eighty-seven board pins. Address checks use all sixteen bits before the wrapper indexes the physical eight-bit address. The memory outputs are synchronous and hold when disabled. halted and fault become persistent only after the corresponding stop token reaches WB. This is the external contract that makes the following pipeline alignment meaningful.

Sources: 16位流水线CPU核心设计文档 v1.4 (2026-10-08), §§1–4 §2.2; rtl/sync_memories.v

# 5. Datapath composition

Presenter B; 65 seconds.

Follow the instruction from left to right. IF sends PC_fetch to instruction memory. ID decodes the returned word, reads the register file and extends the immediate. EX first forwards both actual register sources, then selects ALU inputs. Arithmetic and logic share exec_value with memory address calculation. Store data follows a separate path. MEM accesses data memory or passes a normal result onward. WB selects the normal result or load output, then writes the qualified register and flag fields. The feedback paths return M and W results to EX, and WB data to the ID read ports. Data, control, PC and validity belong to the same instruction throughout.

Sources: 16位流水线CPU核心设计文档 v1.4 (2026-10-08), §§1–4 §2; rtl/datapath_core.sv

# 6. Pipeline payload and write qualification

Presenter B; 50 seconds.

The pipeline registers preserve ownership. ID/EX keeps source indexes and values, the extended immediate and control. EX/MEM keeps execution value, store data and candidate flags. MEM/WB keeps the writeback selection, destination and candidates. A bubble is valid zero, so stale data cannot act. Register and flag writes depend on the WB instruction’s own validity and fault status. A front-end stall or a younger memory fault does not cancel an older qualified WB write. Successful STR creates a WB bubble, while a faulting STR retains a valid stop token. The distinction is essential for orderly fault completion.

Sources: 16位流水线CPU核心设计文档 v1.4 (2026-10-08), §§1–4 §§2.7,3.4; rtl/datapath_core.sv; tb/tb_datapath.sv; datapath.log

# 7. Synchronous memory alignment

Presenter B; 45 seconds.

Address and enable are stable during a stage. The memory samples them at the ending rising edge. Its registered output then serves the next stage, alongside tags captured at that same edge. We do not add a second same-edge IR or MDR register. For a load, the MEM request and its destination are captured together; the resulting DM output supplies WB. Instruction memory holds its previous output when a load-use stall disables fetch. The deliverable includes synthesizable native synchronous memory models and tests their connections. A different vendor-IP read latency would require a new alignment check.

Sources: 16位流水线CPU核心设计文档 v1.4 (2026-10-08), §§1–4 §2.3; rtl/sync_memories.v

# 8. Two-level CLA arithmetic

Presenter C; 60 seconds.

The ALU retains PASS_B, ADD, SUB, AND and OR as internal operations. ADD and SUB use one complement-and-carry path: subtraction flips b and sets the initial carry to one. Four CLA4 groups calculate bit propagation and generation. A separate group network computes K1 through K4 directly from the group P and G values. We do not chain one group’s output carry into the next group’s input. Group P and G are independent of carry-in. The source and RTL analysis view establish that structure. The FPGA mapping is a separate view, and by itself does not establish a speed advantage.

Sources: 16位流水线CPU核心设计文档 v1.4 (2026-10-08), §§1–4 §2.4.3; rtl/cla16.v; eda/rtl_cla16.pdf

# 9. Candidate flags and architectural state

Presenter C; 35 seconds.

The ALU produces combinational candidate signals. The pipeline carries them to WB. ADD and SUB assert CVW, while CMP asserts ZW. Memory address addition does not write flags. For subtraction C means no borrow. V means signed overflow, so it uses a separate condition. A recent CMP candidate can bypass to a following JZ before architectural Z updates, but only when that producer is valid and has ZW. A zero candidate must override an older one.

Sources: 16位流水线CPU核心设计文档 v1.4 (2026-10-08), §§1–4 §2.4.4; rtl/flags_reg.v

# 10. ADD immediate through the datapath

Presenter C; 50 seconds.

Use machine word 5001 at PC zero with R0 equal to 7FFF. ID selects the old Rd and zero-extends the immediate. EX forwards the latest R0, selects a and b, then the CLA produces 8000, carry zero and overflow one. These candidate values enter EX/MEM, pass through MEM without a memory request, and reach WB. At the fifth ending edge, RF receives 8000 and C/V receive zero and one; Z holds. The candidate in EX is not yet architectural state. Every stage shown belongs to this instruction, while other instructions occupy other stages in parallel.

Sources: 16位流水线CPU核心设计文档 v1.4 (2026-10-08), §§1–4 §3.2.1; diagrams/instruction_add.svg

# 11. Load and store use different result paths

Presenter D; 60 seconds.

For 2BFF, LDR R2 from R3 minus one, the base comes from forwarded Rs and the offset is FFFF. With base 0020, the address is 001F. MEM checks the full address and performs a read. WB writes the returned memory value, not the effective address. Store uses the same address calculation, but forwarded Rd travels separately as store_data. It writes DM at the MEM ending edge and has no RF or flag write. Both source paths need forwarding. Success store has a WB bubble; an illegal-address store keeps a fault token while blocking the memory request.

Sources: 16位流水线CPU核心设计文档 v1.4 (2026-10-08), §§1–4 §3.2.2; diagrams/instruction_memory.svg; T03/T17 logs

# 12. Load-use: hold the front end, advance the back end

Presenter D; 65 seconds.

In the baseline, load at PC six is followed by CMP at PC seven. At cycle nine the load occupies EX and CMP occupies ID. The decoder says CMP actually reads the load destination, so load_use asserts. PC and ID hold, fetch is disabled, and the next EX slot is a bubble. The load still advances to MEM and then WB. At cycle eleven CMP uses the WB load data. Older WB and the cycle-nine MEM store are allowed to complete during the front-end hold. A MOV immediate to the same destination has no old-value source and must not stall. We tested that case separately.

Sources: rtl/datapath_core.sv; tb/tb_datapath.sv; datapath.log; BASELINE trace C9–C11; LOAD_MOV_NO_FALSE_STALL

# 13. CMP to JZ: latest Z and the branch PC tag

Presenter D; 60 seconds.

CMP produces an equality candidate and carries it with ZW. The following JZ selects the latest older valid CMP: MEM first, then WB, then architectural Z. The baseline branch at PC eight resolves in cycle twelve using the MEM CMP candidate. Its own PC tag and signed offset produce target A. The ending edge redirects PC and clears the two younger slots. The wrong-path MOV at PC nine cannot write. If MEM carries an ADD rather than CMP, it has no ZW and must not shadow the WB CMP. We also checked consecutive CMP results, including a latest zero overriding an older one.

Sources: 16位流水线CPU核心设计文档 v1.4 (2026-10-08), §§1–4 §3.2.3; BASELINE/T02/T15

# 14. Measured baseline: 17 cycles

Presenter E; 50 seconds.

The complete benchmark contains eleven static words and ten effective dynamic instructions. The wrong-path MOV does not count. The measured schedule has one load-use stall and one taken branch. HALT starts target fetch in cycle thirteen, enters EX in fifteen, MEM in sixteen and WB in seventeen. At the final WB edge halted becomes one. The register file is eight, two, eight and thirty-two; data memory at thirty-two contains eight. Z, C and V are one, one and zero. This is an actual XSim datapath result under the stated synchronous memory contract. It is not a measured board frequency.

Sources: rtl/datapath_core.sv; tb/tb_datapath.sv; datapath.log; BASELINE case result and trace; spec §4.6

# 15. Fault protection preserves older work

Presenter E; 55 seconds.

T17a combines an older ADD with an out-of-range store. The store address is 0100, so dm_en and dm_we remain zero. The older ADD still writes 8000 and C/V at the same edge. The younger MOV is cancelled. The faulting store reaches WB as a valid fault token, and fault becomes one at that ending edge. This is why successful and faulting STR cannot use the same WB-bubble rule. Other tests check a memory fault defeating an EX branch or HALT, as well as a branch cancelling a younger invalid fetch.

Sources: rtl/datapath_core.sv; tb/tb_datapath.sv; datapath.log; T17a/T16/T18b; spec §3.4–3.5

# 16. Verification evidence and coverage

Presenter E; 45 seconds.

Unit tests check CLA propagation and generation, arithmetic flags, the decoder and flag masks. The main pipeline suite passed 128 programs and 16 reset probes, with all 14 legal opcodes completing. Its independent model checks write intent, destinations, data and final state. A second scoreboard passed 4,696 bounded stress programs and compares all registers, flags and memory after every edge. Precise witnesses establish the required timing conflicts. Large arithmetic spaces remain bounded rather than fully exhaustive.
