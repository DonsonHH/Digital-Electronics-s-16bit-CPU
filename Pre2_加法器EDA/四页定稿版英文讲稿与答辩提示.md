## 1. From Manual Structure to EDA Behavior（0:35）

中文提示：先接同学的门级推导，用同一功能、不同描述方式对照。不要再说同学用了两个半加器；他的PPT是三项进位门级结构。WHAT/HOW指当前抽象层次，不代表设计者完全不考虑硬件。第一页等式为功能概括，第二页给出显式17位实现。

### English script

My teammate has shown how to derive the full-adder gates and connect sixteen stages. My part starts from the same required function, but uses a different design approach. Instead of specifying those gate connections, we describe addition directly in HDL. In short, we specify what the module must calculate, and let Vivado choose the implementation. Both approaches target the same interface and addition function.

证据与边界：Peer pre2-adder-人工.pptx slides 1–3; tested adder_rtl in modules.v; CPU specification §10. Manual design shown by peer uses direct three-term carry gates, not two half-adder instances. The unextended equation on this slide is a mathematical contract; actual HDL on slide 2 extends operands.

## 2. RTL Design and Elaboration（0:45）

中文提示：先指代码扩展，再指1和2，最后指输出拆分。两个RTL_ADD不代表最终两个固定物理加法器。

### English script

This is how Vivado elaborates that arithmetic expression. We explicitly extend a, b and carry-in to seventeen bits. The elaborated schematic then shows two logical additions: first a plus b, then plus carry-in. Follow the marked output: bit sixteen is carry-out, and bits fifteen through zero form sum. This confirms the intended width and arithmetic interpretation. The two RTL ADD symbols are a logical view; synthesis can optimize them rather than preserving two separate physical adders.

证据与边界：User adderrtl analysis.pdf. Code is W=16 specialization of tested adder_rtl. Labels annotate source diagram without changing it.

## 3. Functional Verification（1:05）

中文提示：先用一句解释TB比较，再分别指10–20、20–40、40–50ns。全为十六进制。图中sum_r/cout_r是行为版，Value列跟随0ns光标，不能用它解释40ns。典型波形与穷举是两次不同用途的运行。

### English script

The testbench computes a seventeen-bit expected result and compares it with carry-out joined to sum. Any mismatch triggers an error. Here is the original Vivado waveform for the behavioral adder. Between ten and twenty nanoseconds, zero plus zero with carry-in one gives one. Between twenty and forty nanoseconds, hexadecimal 00FF plus one gives 0100, testing carry across bit positions. Between forty and fifty nanoseconds, FFFF plus one gives a zero sum and carry-out one. In all three cases, the full observed result matches expected_add. These are representative short-test waveforms. Separately, the exhaustive binary-input check completed with zero mismatches; the detailed coverage logs are included for inspection.

证据与边界：Original screenshot codex-clipboard-74629f41-0443-4163-b259-ab591a98422e.png, cursor remains at 0ns. TB excerpt simplified; actual short TB waits 10ns before comparing, full TB waits 1ns. Exhaustive coverage is two contiguous ranges [0,1207959552) and [1207959552,8589934592), verified source hashes. No netlist/board equivalence claim.

## 4. From RTL to FPGA Hardware（0:35）

中文提示：左图只作整体背景，主要指右边LUT和CARRY4。只说明映射，不凭图片宣称更快。穷举结果口头一句即可，被问再解释2^33和分段覆盖。

### English script

Finally, synthesis maps the arithmetic description onto FPGA resources. The small view provides context; the enlarged region shows the important parts. LUTs implement local logic, while CARRY4 provides dedicated carry-chain resources. Our takeaway is the full EDA path: describe the arithmetic, inspect the logical interpretation, verify the output, and inspect the hardware mapping. The self-checking HDL tests found zero mismatches. Timing and board-level performance require separate evidence.

证据与边界：User adderrtl.pdf; mapped schematic only, source project and constraints not independently bound. Functional coverage of tested HDL: 2^33 binary inputs, two contiguous runs, completion 2026-09-15 15:03:13, not a post-synthesis netlist test.
