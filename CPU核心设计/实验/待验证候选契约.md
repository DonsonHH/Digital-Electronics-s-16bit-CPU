# 阶段4至5候选契约

状态：待实现和验证。此文件是后续实验依据，不表示候选通过或已替换AC1。阶段3完成独立Review后再运行性能基线与候选实验。

当前布线关键路径为同步DM返回→WB选择→操作数前递→ALU加减进位→m_c；先针对前递/MUX比较，保留原17位加减表达式及CPU周期。目标保持EES-331、100MHz、同RAM和VIO配置、同实现策略；LUT采用routed utilization物理计数，不能使用逻辑原语总数。

组合候选可将优先级选择与数据MUX分开：在完整always组合块中按原if语义产生确定的one-hot选择，之后对保存值/M/W数据作掩码OR。保持M有效非load优先W，M匹配load阻断旧W且保留saved占位；输出sel/blocked与原逻辑一致。不能直接用含X条件的ternary替代原if，导致未使用输入X泄漏。至少检查131072前递控制组合、原九套、独立48例及受影响X/Z、错误注入，并要求架构和原逐拍规则相同。若综合已等效优化且无收益，保留基线。

WB到MEM候选仅允许STR数据延迟，不允许基址延迟：ID中相邻LDR与STR的Rd相关但Rs不相关时不暂停；Rs也相关仍停1拍。EX中只有有效无故障STR、原ALU输入为Rs和立即数、仅blocked_rd且未blocked_rs时允许不在EX消费Rd。m_rd已有STR数据源编号，复用它，新增1位m_store_pending即可；不新增另一套源标签。

pending随有效EX/MEM槽传递；被取消或reset必须清0。MEM中pending要求有效无故障WB load/RW且w_rd=m_rd，然后用已选wb_data作为DM写入数据，否则禁止写并形成MEM内部控制fault（原因5）。地址越界仍为原因4；同一槽优先已携fault，再地址fault，再未就绪fault。MEM故障必须胜过年轻EX事件，老WB继续完成。故障/停止标记继续至WB，STR仅MEM写一次，WB标签无写入。后端在前端stall时继续推进，不能转发load的EA或绕过未就绪新生产者读取旧W值。

两类候选验收不同：组合候选保持旧周期；WB/MEM候选保持ISA架构事件顺序和最终状态，并验证新停顿规则，不能强迫旧CSV逐字节一致，也不能悄悄改冻结48例的原期待。需要候选专用时序检查；原包保留原字节。至少覆盖R0、Rd=Rs、地址与数据双依赖、相邻/隔一条、多生产者、load故障、错误路径store、HALT、reset和无效槽。

故障与reset不能机械套用正常HALT的周期公式。例：故障LDR之后的年轻STR数据相关可能由1停顿变0，但故障token自身排空周期未必减少。旧reset用例若等待被消除的数据stall，刺激条件需要候选专用处理或改用真实基址stall见证，不得关闭timeout或静默遗漏reset覆盖。late资格还应匹配合法STR控制组合，未知/非法组合不得借此绕开原blocked检查。

拟增加copy_checksum工作负载：MOV R3,#32；MOV R1,#0；8组LDR R0,[R3+i]/STR R0,[R3+i+32]；8组LDR R0,[R3+i+32]/ADD R1,R0；HALT。DM32至39初值FFFF,0001,8000,7FFF,1234,A5A5,5A5A,0000。独立求和预期R1=1232、R0=0、R2=0、R3=32，Z/C/V=0；8次store，最后地址71数据0。
