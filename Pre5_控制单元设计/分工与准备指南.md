## 全员先理解什么

先看第2、3、5、13页，再读自己负责的讲稿。第一次阅读不必追完所有源码，但下面这些概念全员都要能用中文解释。

| 术语 | 在本CPU里的意思 |
|---|---|
| CU与数据通路 | CU决定选择什么数据、执行什么操作、是否允许写入；ALU、RF、PC、存储器等实际完成相应动作 |
| IF、ID、EX、MEM、WB | 取指、译码/读寄存器、运算/判断、数据访存、最终寄存器/标志写回及完成；同拍可以属于五条不同指令 |
| IM、DM、RF、EA | 指令存储器、数据存储器、寄存器组、有效地址。本文地址与机器字默认十六进制 |
| RW、MR、MW、ZW、CVW | 写寄存器、读DM、写DM、写Z、写C/V的意图；意图为1还不等于实际写使能为1 |
| valid、PC标签、fault | 该槽是否有指令、是哪条指令、是否携带故障。气泡valid=0；不能只看残留数据判断它还会执行 |
| Z、C、V | Z是CMP的相等结果；ADD/SUB写C/V而保留Z。减法C表示无借位。地址加法不改标志 |
| Forwarding与WB到ID旁路 | 不等RF正式保存就使用合格的较新结果；M非load优先于W，RF另有同周期写回到读端口的旁路 |
| Stall与Flush | Stall保留必要的年轻指令等待数据，本设计load-use停一拍；Flush取消错误路径，不能取消应完成的老指令 |
| RUN与DRAIN | RUN是全局运行模式，不是单条指令的IF阶段；DRAIN停止接收年轻工作，让老指令和停止token走完 |

每讲一条指令，都按同一条逻辑链回答：读哪些真实源 → EX选择及运算 → MEM是否访问DM → WB允许哪些写入 → PC如何继续或重定向。用`valid=1但不写入`与`valid=0的bubble`作比较，不能把“没有RF写入”说成指令已经退出流水线。

为什么第13页不是一圈IF→ID→EX→MEM→WB？那种全局状态循环会让五级串行工作。本设计中，每条指令的推进由第5页的随行控制和各级valid描述，全局mode图另外描述运行、排空与停止。讲解时把第2、5、13页连起来，这才对应当前真实实现，而不是照搬课件里的另一个实验CPU。

## A 如何准备

按“输入、译码与控制流水、反馈仲裁、状态与写入资格、输出”的顺序解释第3页。CU是硬连线逻辑职责的集合，没有新加`cu.v`或微码ROM。译码、EX前递有独立模块；其余主要逻辑在`datapath_core.sv`内，WB到ID旁路在RF内。

五级同时处理不同指令；RUN是运行模式，不是单条指令的IF状态。老师Lec18用于参考控制字、反馈和状态图的方法，不能把其中串行实验FSM、握手或异步低有效复位照搬到当前CPU。

## B 如何准备

对照译码器找到MOV立即数、算术立即数、LDR、STR、CMP。MOV立即数不读RF；算术立即数读旧Rd；LDR只读Rs基址；STR读Rd数据和Rs基址；CMP读两源。R0普通可写，未使用的编码字段匹配不能触发假停顿。

第5页：在ID使用的是扩展模式，扩展后的立即数仍进入EX。控制与本条pc/valid/fault对齐，不能用当前ID控制较老EX。PC标签保留指令身份，不是额外的RF写入许可。

第6页：写入意图还需valid、无故障、对应mode及未复位资格。reset优先，其次老MEM fault、EX fault/HALT、EX redirect、load-use、正常推进。年轻故障不能禁止更老的合格WB完成。

## C 如何准备

第7页是BASELINE的`4100`：EX C5从W取得R0=5、从M取得R1=3，得到8；C7结束边沿写RF及C/V，Z保持。不能把不同级同一列的值当作同一指令。

第8页使用当前机器字STR=`9300`、LDR=`8B00`。基址由Rs前递后加符号位移；STR的Rd数据独立前递并保存。STR在MEM写一次，随后WB仍valid但不写RF/标志；LDR写回返回数据，不能写有效地址。地址ADD不改Z/C/V。

第9页的TB初值独立于BASELINE。C3保持PC/D并向X插bubble，C4老load继续，C5从W提供7，C6结束边沿写DM[0021]，C7保留STR有效WB。只有一次load-use停顿；C7禁取指来自后续分支。阶段和控制取边沿前，写入结果在该列结束上升沿生效。

## D 如何准备

Z候选优先M CMP、再W CMP、最后保存的Z。新候选0必须覆盖旧1。ADD/SUB只写C/V，不能挡住更老CMP的Z。JZ目标使用自己的`x_pc+1+signed offset`。

第11页C7的pc5只是请求地址，`im_en=0`，没有接受新响应；C8才接受目标取指。老STR、CMP及分支自身继续，年轻F000被取消，不能一译码就不可逆停机。未取分支不flush。

第12页T16：EA=0100越界，MEM的load比EX HALT老，因此禁止DM访问、取消HALT，C4后为DRAIN_FAULT、C5后为FAULTED。周期编号属于本用例，不拼接BASELINE绝对时间。

## E 如何准备

五个状态编码为RUN=0、DRAIN_HALT=1、DRAIN_FAULT=2、HALTED=3、FAULTED=4。正常推进、停顿和重定向均可留在RUN。固定延迟故障检测下，没有DRAIN_HALT到DRAIN_FAULT的转移：老故障在HALT获准前已优先处理。

`drain_done`要求当前有效WB停止token，且下一拍四级valid全空。T07中老load在C5仍写R1，HALT到C6 WB消费才置halted，不能在MEM提前停。同步reset清在途状态及RF/标志/PC，但已提交DM不回滚。

九套回归和独立48例既查最终状态也查逐拍见证。整个CU不能笼统称纯Moore；halted/fault是mode译码，其余控制还依赖流水状态及反馈。有限测试不等于全部CPU状态、硬件时序或下板通过。

## Vivado准备和排练

建工程、复跑和波形打开方法统一见README。不要各自编辑原CPU工程；本包RTL逐字节对应AC1基线。

建议波形信号：公共看clk/rst、mode及各级valid/pc；C看load_use、im_en、前递选择、wb_data、store_data和DM使能；D看CMP候选、z_effective、redirect、branch_target和fault_event；E看mode_next、停止token、valid_next及drain_done。

第一遍照Word完整讲并指图，第二遍只看每页核心问题讲。A交给B解释译码，B交给C讲典型执行，C交给D讲分支，D交给E讲状态机。第16页结束，备用页只在答辩时跳转。超时时压缩重复缩写解释，保留结构、真实控制过程及状态图。

必须能回答：为何不是全局IF到WB状态循环、valid如何对齐、为何MOV立即数不误停、为何不能转发load地址、STR为何WB有效、CMP/JZ为何不用等WB、老fault为何优先HALT、为何停止条件看next valid，以及测试能证明和不能证明什么。

## 共同的Vivado操作

1. 每人使用本包的一份副本，打开`Vivado/project/cpu_v16.xpr`。本机基线是Vivado 2025.2、`xc7z020clg484-1`。工程入口不等于已经综合、实现或下板。
2. 在源码中找到`isa_decode.v`、`datapath_core.sv`、`operand_forward.v`、`regfile4x16.v`。按第3页标出“谁产生意图、谁仲裁、谁保存状态、谁真正写入”，不要寻找并不存在的独立`cu.v`。
3. 基准仿真用`tb_datapath`作为Simulation Top并运行到完成；短的load-use示例用已有`tb_trace`作为Simulation Top。切换顶层后重新启动对应仿真，不要把两个TB的周期混在一起。运行脚本和已有原始记录见README。
4. 看波形前先加入相关内部信号和`clk/rst`；若前面没有记录所需信号，重新开始仿真，不能仅在结束后加入就声称看到了过去的完整变化。`tb_datapath`的核心层次是`/tb_datapath/dut/core/`；`tb_trace`为`/tb_trace/test/dut/core/`。
5. 同时打开对应`Vivado/control_traces/*.csv`。`cycle`是该用例自己的拍号，`time_ps`是原仿真的绝对皮秒位置，除以1000才是ns。`pre_`表示结束边沿前的阶段/控制，`post_`表示该边沿更新稳定后的状态。读PPT中的“C5”时先定位该用例，不能直接跳到整个仿真的第5拍。
6. 每人保留一处自己能解释的源码定位和一段实际波形/CSV，不要求重新制作PPT截图。要能先说出预期值，再指着实际结果解释，而不是只展示PASS或背讲稿。

## 全组最后如何验收准备情况
