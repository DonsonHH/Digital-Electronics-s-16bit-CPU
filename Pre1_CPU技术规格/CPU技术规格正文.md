# 16位顺序流水线CPU技术规格

核心架构 实现约束与验证规范    课件核对版    2026年9月9日

本规格定义一颗16位、单发射、顺序执行的五级流水线教学CPU。保持最新21页汇报中的13种指令编码，采用独立IM与DM、固定同步存储接口、通用数据转发、load-use停顿、CMP至JZ标志转发与EX分支冲刷。STR在MEM完成存储动作，不执行寄存器写回。基线没有Scheduler、ROB、缓存、通用协议Adapter或强制硬件性能计数器。

目标是形成可以继续实现、测试和优化的统一技术规格，而不是压缩成课堂讲稿。规范分为三层：第1至9章定义核心功能与外部可见行为；第10至14章明确模块、时序与验证义务；附录记录错误处理、候选优化、资料依据和建议取舍。附录中的正确性约束仍必须满足，位置靠后不代表可以省略。

## 设计状态

已完成：课件版本盘点、设计逻辑核对、ISA与周期模型差分检查、基本算术/扩展布尔检查，以及固定同步读边界的抽象检查。未完成：实际RTL实现、Vivado存储IP仿真、综合、布局布线时序、CDC检查和下板验证。本文不声称得到最优Fmax、最小面积或最高评分。

本轮没有重做或修改任何PPT，也没有覆盖先前设计文档。最新用户汇报作为ISA与程序的事实基准；老师课件作为课程约束和设计方法来源；具体五级控制、端口与异常策略是本规格的设计选择。新旧规则冲突时以本规格中标为“基线”的约定为准，不能分别从几份版本各选一段实现。

## 本版关键优化

1. 将“核心必须功能”和“验证工具、可选诊断”分开，去掉强制completion counter和对全部指令统一commit的依赖。
2. 分开逻辑存储延迟契约与Vivado实现方式，但不允许额外寄存器悄悄改变数据/标签对齐和load-use罚时。
3. 合并每条指令互斥使用的ALU result和有效地址为EX/MEM.exec_value，避免无用途地同时保存两份16位值。
4. 为MUX、加减器、比较器、寄存器组、控制译码和流水边界给出实现接口与验收标准。
5. 明确错误停止不是完整异常系统；必要的年龄优先级和错误路径取消保留，诊断地址和原因码为可选项。
6. 用可复现差分测试和公平性能比较决定是否加入进一步优化，不以“高级模块更多”作为更好CPU的标准。

# 2 架构状态与指令格式

架构可见状态包括R0至R3、Z标志、程序控制流和DM内容。R0是普通可写寄存器，不采用其他ISA的常量零规则。算术结果为16位模运算，CMP只判断16位位串是否相等；不增加有符号大小比较、进位分支或溢出异常。

PC_fetch是微架构前端指针，不等同于“最后完成指令地址”。分支指令携带其自身pc，JZ以该pc+1为相对基准。初始复位PC_fetch=0、R全0、Z=0、流水valid全0，halted和fault为0。IM程序镜像在加载设计时初始化，DM初值由测试环境或程序负责。

| 字段 | 位范围 | 含义 |
| --- | --- | --- |
| Opcode | 15至12 共4位 | 0至C有效 D至F非法 |
| Rd | 11至10 共2位 | 目标或第一源 STR中表示写入的数据 |
| Rs | 9至8 共2位 | 第二源或访存基址 |
| Imm | 7至0 共8位 | 无符号常数或有符号位移 |

每个存储地址对应一个16位字，因此顺序取指PC_fetch增加1。最新PPT中0xB001在pc=6表示JZ +1，取分支目标为8。地址计算先按16位截断，再检查物理范围；不能直接丢弃高地址位而误访问低地址RAM。

## 扩展与无关字段

MOV、ADD立即数与JUMP用零扩展ZExt；LDR、STR位移和JZ用符号扩展SExt。0x7F两种模式都是127，0x80零扩展为128而符号扩展表示-128，0xFF分别为255和-1。HDL中须显式生成16位结果，避免隐式signed规则蔓延。

未使用字段在程序镜像中置0、硬件译码忽略。bubble必须用valid=0表示，不能用MOV R0,#0冒充NOP，因为它会改写R0。D至F可能由程序跑飞或错误镜像产生，不能因“保留”而把其RegWrite/MemWrite设为综合don't-care。

## 指令编码检查

word = (opcode << 12) OR (rd << 10) OR (rs << 8) OR (imm AND 255)。字段限制分别为4、2、2、8位。编码器与反向译码器均需检查输入范围，不允许越界参数悄悄覆盖相邻字段。

# 3 ISA完整语义与副作用

| Hex | 指令 | 结果 |
| --- | --- | --- |
| 0 | MOV Rd #u8 | R[d] = ZExt(u8) |
| 1 | MOV Rd Rs | R[d] = R[s] |
| 2 | ADD Rd #u8 | R[d] = low16(R[d]+ZExt(u8)) |
| 3 | ADD Rd Rs | R[d] = low16(R[d]+R[s]) |
| 4 | SUB Rd Rs | R[d] = low16(R[d]-R[s]) |
| 5 | AND Rd Rs | R[d] = R[d] AND R[s] 按位 |
| 6 | OR Rd Rs | R[d] = R[d] OR R[s] 按位 |
| 7 | JUMP #u8 | 无条件目标ZExt(u8) |
| 8 | LDR Rd [Rs+s8] | R[d] = DM[low16(R[s]+SExt(s8))] |
| 9 | STR Rd [Rs+s8] | DM[low16(R[s]+SExt(s8))] = R[d] |
| A | CMP Rd Rs | Z = (R[d] == R[s]) 不写R |
| B | JZ #s8 | Z有效值为1则跳到low16(pc+1+SExt(s8)) 否则顺序 |
| C | HALT | 不执行更年轻指令 排空后停止 |

数据指令的目的寄存器只有Rd，其余寄存器保持。CMP以外的指令保持Z。STR的Rd是数据源，不是写目标；LDR的Rs是地址基址，不是要加载的数据。这些规则必须体现在源使用掩码和冒险检测中。

## 功能发生的阶段

MOV、ADD、SUB、AND、OR在EX计算，在WB写R。LDR在EX算地址，在MEM读数据，在WB写R。STR在EX准备地址及已转发的数据，在MEM写DM；没有WB动作，对应WB槽为bubble。

CMP在EX比较、WB更新架构Z，紧随的JZ可以使用尚未写回但来自较老CMP的转发结果。JUMP/JZ在EX重定向PC_fetch，其后携带的无写回标签只用于排空或测试跟踪，不在WB重新修改PC。HALT在EX挡住年轻指令，较老指令结束后置halted。

“Write-back”统一指寄存器或标志写回，不能再将其当作STR提交内存的阶段。STR不执行WB不意味着下一条指令跨级占用空WB槽；所有后续指令仍每拍推进一级。

# 4 五级流水线与存储并行

@image pipeline_architecture.png

图1 逻辑流水边界与依赖控制。图中模块表示职责，不锁死IP内部寄存器的物理位置；每个边界均须保存正确的数据、控制、valid和必要pc标签。

| 阶段 | 必须完成的工作 |
| --- | --- |
| IF | 给IM地址 正常推进取指或保持/重定向 |
| ID | 译码 寄存器读及WB读旁路 产生控制和源掩码 |
| EX | 转发选择 ALU/EA计算 CMP比较 JUMP/JZ决定 |
| MEM | 访问DM或传递普通结果 STR在此完成 |
| WB | R或Z写回 HALT尾部排空完成 |

一条LDR在MEM读DM时，较新的指令可同时在IF读IM。这是真实并发，区别于全局FSM按F/D/X/M/W依次做完一条再启动下一条。普通结果在MEM经过传递槽再进入WB，使唯一寄存器写口保持有序，避免LDR与较年轻ALU指令同时抢写口。

## 寄存器边界

IF/ID保存指令、pc及valid；ID/EX保存已译控制、源索引、源值、立即数、目的和pc；EX/MEM保存执行值、STR数据和控制；MEM/WB保存写回选择与结果标签。每组valid=0时禁止该级所有副作用。对无效载荷不必强制反复清零，具体复位策略见实现章节。

## 执行值的合并

EX/MEM.exec_value为16位：普通运算时是ALU结果，LDR/STR时是EA。两者在同一条指令中互斥，不需要同时保留独立Result和EA寄存器。CMP结果为独立1位cmp_z；STR仍须独立16位store_data，不能与地址合并。

# 5 固定存储接口与Adapter边界

## 核心契约

IM与DM在同一时钟域，使用固定的一阶段同步读：本阶段地址与en在结束边沿前稳定，边沿后数据供下一阶段使用。每阶段每个端口最多一次操作，吞吐可为每周期一次；单次延迟和吞吐不得混淆。指令和DM读数据必须与其valid、pc、目的寄存器及写使能同步到达消费阶段。

谁承担载荷存储属于实现选择，但不能增加未经控制的延迟。允许IP输出存储承担IF/ID指令或MEM/WB读数据；也允许其他等价组合与显式寄存器实现，只要同一边界契约成立。同步BRAM之后再加同沿IR/MDR采样不自动等价，可能多一拍；必须通过边沿测试证明。

## 原生接口

| 组别 | 输入CPU | 输出CPU | 逻辑位数 |
| --- | --- | --- | --- |
| 指令 | im_dout 16 | im_en 1 im_addr 16 | 33 |
| 数据 | dm_dout 16 | dm_en 1 dm_we 1 dm_addr 16 dm_din 16 | 50 |
| 基础控制 | clk rst 各1 | halted fault 各1 | 4 |

最小核心接口合计87位，验证标签、诊断输出和可选监控不包括在内。它不是FPGA物理引脚数。没有req/ready/err，也没有两个仅标“Memory timing”的独立Adapter。存储器模块可保留IP实例封装，但不能隐藏额外等待、转换或队列。

## 基线容量及保护

初始IM、DM各为256个16位字，两者独立地址空间。IM只读，DM可读写。地址为16位完整值，接入物理低8位之前检查高位；越界停止，禁止非法DM写入。不引入默认LED映射或外部总线副作用，若以后增加MMIO需单独定义读写时序和地址表。

## 功能换取的限制

删除Adapter的前提是锁定以上契约。未来若增加额外IP输出寄存器、可变延迟总线、缓存或跨时钟设备，需修改流水边界或加入明确的互锁协议。不能一方面声称固定五级及1拍load-use，另一方面允许任意存储延迟而不改变控制。

# 6 数据转发与源使用掩码

| 指令类别 | 读取Rd旧值 | 读取Rs值 | EX用途 |
| --- | --- | --- | --- |
| MOV立即数 | 否 | 否 | 立即数 |
| MOV寄存器 | 否 | 是 | PASS_B |
| ADD立即数 | 是 | 否 | Rd加立即数 |
| ADD SUB AND OR寄存器 | 是 | 是 | 两寄存器运算 |
| LDR | 否 | 是 | 基址加符号位移 |
| STR | 是 | 是 | Rd数据 Rs基址 |
| CMP | 是 | 是 | 相等比较 |
| JUMP JZ HALT | 否 | 否 | JZ另有Z依赖 |

每个实际使用源分别选择最新值：有效EX/MEM的非load寄存器生产者优先，其次有效MEM/WB写回值，最后ID/EX保存的值。匹配同时检查源use、目标索引、valid和RegWrite。R0参与所有匹配，不存在rd!=0例外。

EX/MEM中的LDR尚无结果，其exec_value是地址，严禁作为load数据转发。若最近生产者未就绪，不能越过它使用更老的同名值。连续WAW生产者优先选择最近者，forward selector不得简单按结果非零判断有效。

## STR的两条相关路径

STR基址与写入数据都在EX进行转发，然后将EA与store_data锁入EX/MEM。MEM只使用这两个保存值。基线对load至STR基址或数据相关均停顿1拍，不采用额外WB至MEM晚转发；该晚旁路作为可选优化，必须证明节省的周期与新增路径代价。

## WB到ID读旁路

WB本拍即将写入的地址等于ID实际读取地址时，ID显式捕获WB写回值。不能依赖同一边沿仿真进程执行先后，也不能假定所有寄存器实现都是write-first。该旁路处理跨三条距离的依赖，不能由EX旁路完全代替。

## 选择网络

先完成源值转发，再依据Opcode选择ALU输入；不要先将立即数放入源槽再参与错误的寄存器比较。普通ADD/SUB/AND/OR用转发Rd与转发Rs；ADD立即数改用ZExt；访存用转发Rs加SExt，并单独保留转发Rd作为STR数据。

# 7 停顿与控制冒险

load-use条件为：ID/EX是有效LDR，且其目的索引匹配IF/ID的实际读取源。满足时保持PC_fetch和IF/ID、禁止IM覆盖当前ID载荷，ID/EX.valid清0；较老EX/MEM、MEM/WB继续前进。这是插入bubble，不是把LDR自身冻结在EX。

LDR R1后接ADD R2,R1在基线中停1拍；LDR R1后接MOV R1,#5没有源依赖，不停顿。LDR结果在MEM结束后可用于下一拍EX转发。若存储契约变化，1拍结论失效，必须重算。

## 标志转发

CMP在EX产生cmp_z，WB更新架构Z。JZ在EX按以下顺序取标志：EX/MEM有效CMP、MEM/WB有效CMP、架构Z。0也是有效结果，必须能够覆盖旧的1。两条连续CMP后面的JZ只读取最近的较老比较结果。被flush的CMP没有转发资格，也不写Z。

## 分支规则

无动态预测器，默认顺序取指。EX的有效JUMP或取分支JZ发出redirect，目标根据该指令pc计算。该边沿更新PC_fetch、清两个年轻槽IF/ID及将进入ID/EX的载荷，取消错误路径当拍取指；更老MEM/WB继续。下一周期开始目标IF。没有delay slot。

不取JZ不冲刷。取分支损失两个年轻槽是本实现约定，不是所有流水CPU的常数。若以后EX前移到ID，必须重新处理比较源和Z的就绪时间，不能只缩短箭头。

## 生命周期不变式

valid=0禁止RegWrite、MemWrite、FlagWrite、redirect、halt请求和错误激活。前端stall不阻断老指令完成。redirect取消年轻指令，即使年轻指令恰好是HALT或非法Opcode。更老MEM地址错误优先于EX重定向；该优先级属于正确性，不应因“异常太复杂”而省略。

# 8 STR与停止行为

STR completes its architectural action in MEM. It has no WB action. The corresponding WB slot is a bubble.

STR成功写入DM后，本条不占用有效WB数据槽，其他指令仍按固定每拍一级前进，不跨级抢占空槽。全局PC_fetch不由STR完成来加1，而是早已在正常发起取指时前进。最新汇报中的“PC updates in W”须由新取指规则替代，不能仅删掉STR的WB格。

## HALT核心语义

HALT在EX确认后停止新取指、清年轻槽；自身作为结束标记向尾部流动，待更老操作完成再置halted。HALT后面的STR不允许写内存，HALT前面的LDR必须能写回。被更老分支冲刷的HALT不能关停前端。停止地址可以保留为可选调试寄存器，不是保持超前PC_fetch等于HALT地址。

## 错误停止的最小范围

非法Opcode或越界访问停止流水，并保证故障前较老指令已完成、年轻指令没有产生副作用。它是终止保护，不提供中断、异常向量、返回、重试或软件恢复。具体fault token和年龄控制在附录A定义，不能用无优先级的全局清空替代。

## 计数器不属于核心必须状态

完成事件、周期统计、源指令序号和性能计数器默认属于测试平台或可选调试层。核心只需要保证真实数据与控制行为。测试可通过层次化访问或bind观察WB写回、STR的MEM写入与valid，不强制增加completed_count、store_complete外部端口。

如果测试记录每条动态指令，必须包括不写寄存器的CMP、分支和HALT。STR在MEM与较老WB可能同拍结束，监测器先记录WB再记录STR，统计可增加2；这只是观测口径，不是提高到双发射，也不是CPU功能额外复杂度。

# 10 MUX加减器与CMP实现

## 课程推导与实际综合分开

2选1单比特MUX用y=(NOT s AND a) OR (s AND b)，16位为并行复制。全加器sum=x XOR y XOR cin，cout=(x AND y) OR (cin AND (x XOR y))。可由两个半加器和或门实现，也可写等价HDL。以上对应L01、L14、L16和L18的组件设计方法。

加减共用一个进位网络：b_mod=b XOR {16{sub}}，cin=sub。sub=0得到a+b；sub=1得到a+NOT b+1。显式将输入扩为17位计算以保留cout，CPU结果截低16位；cout与有符号overflow不是同一个量，不能将“全加器进位”等同于全部溢出。

## 推荐实现

教学验证保留人工16位纹波版本；FPGA基线优先使用清晰的算术HDL让综合器推断专用进位资源。AMD 7系列提供专用carry逻辑，推断映射仍须检查综合网表。[A1] 不先锁死CPU必须使用手工门级纹波，也不承诺手写CLA必然快于工具推断版本。

超前进位推导采用无歧义定义g_i=a_i AND b_i，p_i=a_i XOR b_i，c_(i+1)=g_i OR (p_i AND c_i)。课件某页把已乘cin的项也命名为P，紧邻页又使用不同简写；实现规格统一以上定义，防止级联推导时重复混用。

## CMP实现

只比较相等，建议eq=NOT reduction_OR(a XOR b)，综合为平衡归约网络；无需串行16级相等链或复用长减法器再判断零。是否独立比较器改善时序需看综合结果，但功能上与a==b一致。CMP结果不连同ALU carry写入额外CF；ISA只定义Z。

## 验收

单比特MUX和FA各穷举8种输入。4位加法穷举512个a/b/cin组合；16位覆盖长进位、0、全1、交替位与固定随机向量。加减验证同时检查低16位结果与内部cout，有符号overflow单独计算核对。CMP测试相等、每一位单独不等、全0/全1和随机位串；扩展器穷举256个输入的两种模式。

# 11 寄存器与HDL实现纪律

四个16位通用寄存器只有64位数据，采用触发器阵列和组合读MUX有利于保证两读一写及WB读旁路，不必强行映射为块RAM。写端按有效we选择唯一目标，其他寄存器保持；R0可写。Rd等于Rs的指令使用同一旧值，经转发后定义明确。

流水payload中保留影响后续级行为的字段，删掉已经消费且不再用于调试或错误定位的冗余字段前先做依赖分析。exec_value可合并Result/EA，但store_data不能删，源索引在EX转发前不能删，pc在EX目标形成前不能删。

## 时序编码

时序always使用非阻塞赋值，组合always使用阻塞赋值并覆盖全部分支；采用always @*或在SystemVerilog许可时使用always_comb/always_ff。不要把课件中的半成品、全角标点、占位符或示意大小写直接作为可综合代码。

每个寄存器只有一个过程驱动。复位、flush、hold、load顺序由该寄存器职责决定：ID/EX在load-use时清valid，IF/ID在同事件中hold；不能给全芯片套同一enable。payload可在valid=0时不清零，但valid、关键控制和架构状态的复位必须明确。

## 电气及时钟边界

内部逻辑采用单一时钟和同步enable，不用门控组合clk或按键脉冲作时钟。外部异步按键、开关先同步，去抖是另一项操作，不能与同步器混为一谈。同步器只能降低亚稳态传播概率，不保证“完全消除”。多比特异步数据不能逐位两级同步后就假设字一致。

核心同步复位要求输入跨越有效边沿。板级电源、PLL锁定和异步复位释放的形成放顶层约束，输入输出电平使用实际板卡标准，不将通用5V TTL例图的电平直接用于FPGA引脚。

## 安全化简

K-map和最小项方法用于已定义布尔函数。无效Opcode、可达错误状态以及流水bubble输出不能随意设X优化。课件同时提供最小风险状态处理方法，本方案选安全默认：不写寄存器、不写内存、不重定向，并按停止规则处理。

# 12 时序收敛与性能优化

设计是否更快必须通过目标器件上的最长和最短路径共同判断。建立约束示意为Tclk不小于tCQ_max加tlogic_max加tsetup再计入不利时钟偏差/不确定度；保持约束是最短路径问题。降低主频不自动修好保持时间违例。完整判断以Vivado setup/hold、recovery/removal和实际时钟定义为准。[A2]

优先检查路径：寄存器读到ID/EX；EX转发MUX到ALU或比较器再到目标寄存器；MEM/WB load数据到EX消费者；CMP flag转发到JZ决定再到PC/IM使能；地址范围检查到dm_we。不要只盯adder本体而忽略旁路和控制的串联延迟。

## 基线与候选优化

| 项目 | 当前基线 | 何时尝试优化 |
| --- | --- | --- |
| 进位网络 | 综合推断算术 人工版本作等价参考 | 关键路径确认在adder且同约束比较有收益 |
| CMP | 独立等值归约 | 确认比较器/标志为瓶颈再调整树形结构 |
| 分支 | EX决定 取分支清2槽 | 分支密集程序确有损失且ID数据就绪方案可验证 |
| load至STR | EX捕获数据 相关停1拍 | 晚WB至MEM旁路节省周期且不恶化时序 |
| 载荷复位 | valid和架构状态确定复位 | 删除无效payload复位改善扇出后仍无X副作用 |
| 额外指令 | 保持13编码 | 程序瓶颈证明收益并有新ISA/回归测试 |

不同时加入多项优化再比较总结果。每次保留基线网表、约束、工具版本、程序/数据镜像、资源及周期统计。不能用改变算法工作量或存储延迟的版本宣称硬件加速。

## 性能口径

程序执行时间=C/f，平均CPI=C/N，MIPS=f/(CPI×10^6)。时钟f只有在相应约束下通过实现验证后才可作为可用频率。C包括开始执行至HALT排空的填充、bubble与冲刷，排除复位初始化；N统计有效动态指令，不统计错误路径、bubble或停机空闲。

硬件性能计数器默认不合成，仿真监测器即可统计C和N。若为ILA演示加可选计数器，明确资源开销并对开启/关闭版本公平比较。EES331的100MHz振荡器只是外部时钟来源，不是CPU的实测Fmax。

# 附录A 错误停止与复位的实现约束

本附录定义的副作用保护属于必须功能，stop_pc、fault_pc、cause和性能计数属于可选诊断。移入附录是文档分层，不是允许错误路径写内存。

## 最小错误机制

ID识别非法Opcode并携带fault标记，不立即不可撤销停机，因为它可能被更老EX分支冲刷。非法取指也带fetch_fault标签到EX，错误路径可丢弃。EX确认错误后停前端、取消年轻指令，较老MEM/WB继续结束。MEM越界更老，禁止本次DM访问并取消年轻EX动作；更老WB仍可完成。

不必增加异常处理器、返回地址栈、重试、软件恢复、特权模式或ROB。需要少量有效位和stop_pending状态，配合本身已有的流水年龄即可完成终止保护。排空完成后置fault直到复位。

## 优先级

复位最高；其次是较老MEM错误；然后EX有效错误或HALT；再是EX分支重定向；再load-use stall；最后普通推进。EX的分支、HALT、非法Opcode在合法译码下互斥，若来自不同阶段按年龄处理。不得让年轻停止请求清除较老应写回的结果。

## 同拍可观察动作

当较老WB正常完成而MEM报错时，WB允许写，MEM和年轻级禁止副作用。当EX HALT而较老MEM STR合法时，STR仍需写入。HALT后的年轻STR应在到达MEM前被kill。已接受的较老存储不会因随后错误或复位回滚；不声称完整精确异常系统。

## 复位契约

同步rst在上升沿优先清valid、架构寄存器、Z、前端PC和停止状态；数据RAM不在核心复位过程中逐字清空。顶层决定上电和按钮的复位时长及释放同步，测试在每一种流水占位下检查rst，不能仅在时间0脉冲一次就认为复位覆盖完整。

# 附录B 存储边沿映射与配置记录

核心规格规定的是固定一阶段同步读和每周期可接受一次的吞吐。物理寄存器位置可替换，但替换前后必须满足下表，而不能仅用“实现细节”掩盖新增周期。

| 边沿及周期 | IM路径 | DM读路径 |
| --- | --- | --- |
| 周期k内 | IF地址及en稳定 | MEM的ea与读en稳定 |
| 周期k结束边沿 | 采样地址 同时登记pc和valid | 采样地址 同时登记目的和load控制 |
| 周期k加1内 | dout供ID译码且与标签一致 | dout供WB写回且与目的/valid一致 |
| k加1结束边沿 | ID/EX捕获译码和源值 | RF捕获当前WB load值 |

基线候选使用无额外输出寄存器的同步BRAM或等价固定同步RTL存储。若同步BRAM已经在周期k结束后产生dout，另加一个always @(posedge clk) ir<=dout会读旧dout而多延迟；必须把控制也相应延迟或重定阶段。采用组合读LUTROM加显式IF/ID寄存器是另一种满足整体一阶段边界的实现方式，但它的资源和时序不同，不能称为同一BRAM配置。

## 项目必须记录

记录器件型号、工具版本、IP名称和版本、读延迟、输出寄存器开关、en行为、复位作用、写模式和初始化文件哈希。选择en=0保持IM当前ID载荷时，IP测试必须证明保持；若改成独立ID缓冲，需要重新验证stall、redirect与并发取指，不隐式增加队列。

## 不做无依据保证

IP原语同步输出与逻辑IF/ID、MEM/WB共享存储边界是合法实现候选，不是必须由RTL中的一个单独reg变量代表。额外一级输出寄存器可能提高可用时钟，却会增加相关延迟或阶段数量；优化需比较整个程序时间，不能只报告Fmax变高。

地址越界在物理端口使能前阻断。实现只有256字时，仍保留16位逻辑地址和高位检查；以后扩大容量可改深度参数，但必须同步镜像边界和测试，不擅自改变ISA的16位地址截断规则。

不会为了表现“更好”填满剩余三个Opcode。XOR、移位、加速指令或分支预测只有在基线实现通过、工作量与收益可量化后才进入独立版本；不把潜在功能变成现在的实现义务。

# 附录E 课件语义边界与引用

## 不直接照搬的地方

L02第14至19页以多指令重叠说明流水；L10第6至9、17页同时出现“Pipeline”标题和全局IF至WB循环状态图。单个循环状态机不能独自表示多个级同时工作，因此本规格采用每级valid和随行控制，只借鉴控制字生成方法，不照搬整个实验FSM。

L13/L17的基本Lab ISA第18页与前面的复杂5位Opcode示例不一致；L13备注还明确提示部分JMP编码与代码接口不一致。本文固定最新PPT的13种编码，不把CF、ADDC、SUBB或另一套跳转格式隐式混入。

PC加1或加2由地址单位决定，不仅由数据字宽决定。课件示例有不同内存表达，本文坚持按16位字编址，因此pc+1表示下一条指令。符号扩展只用于已定义的位移字段。

L11第6页给出保持时间下界，第7页有“通常不用关注”的教学简化；实现验收仍检查全部hold/removal约束。L22关于同步系统毛刺的概括也不能外推为任意异步控制、门控时钟或采样边沿都无问题。

L16第17至18页P/G符号表达需要统一；本文使用g=a AND b、p=a XOR b和c_next=g OR p c，不混用已含cin的P项。Carry、unsigned wrap和signed overflow分别命名，避免把课件图中carry/overflow混写当成ISA标志定义。
